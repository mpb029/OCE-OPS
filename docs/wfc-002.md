## Behaviour

- Editor revision checks use the GitHub Contents API's file SHA and corresponding board, including the Git Blob fallback for larger responses. Pages/raw timestamps remain only the existing public-view refresh mechanism.
- An IndexedDB journal retains repository identity, common base/SHA, current draft, local generation and immutable in-flight publication snapshots. The original localStorage board remains a compatibility mirror. A save is acknowledged only after both writes succeed. Browser Web Locks and journal revision comparison prevent silent last-tab-wins saves; competing drafts are kept separately for review/export.
- Publishing captures a snapshot, checks the current authoritative revision, validates the result and uploads with that exact SHA. A 409 fetches again and requires another comparison/review, bounded to three attempts. Other API failures retain the draft and report failure. Edits—including atomic Permit saves—made during upload remain unpublished. Reload checks whether an interrupted candidate actually reached the remote board before resolving its journal entry.
- Stable-ID arrays reconcile at **whole-record** granularity. Independent edits/additions combine; identical edits do not conflict. Different edits to one record, conflicting additions, deletion versus modification and conflicting order require explicit choices. Metadata without reliable record identity is compared conservatively. Unknown fields are retained; no field-level merge of engineering decisions occurs.
- The editor-only sync pill opens review/recovery. Conflicts show project, type, title/ID, changed fields and escaped local/remote records. Choose local or remote, or cancel. Even conflict-free remote reconciliation requires confirmation before publication. There is no force-publish path.
- Missing base metadata and imported backups require an explicit comparison that saves an unpublished reviewed draft; Publish is a separate action. Dirty local drafts are never replaced by a background refresh. Cross-tab review can preserve and reconcile both drafts; unreadable compatibility copies are retained verbatim in recovery storage and exported separately. Nothing is automatically published during recovery.
- Local write failures leave session changes recoverable, report **Local save failed**, retain the original saved copy where writes can be rolled back, and provide immediate current-draft export. Recovery-copy export includes the draft/journal/raw board copies, not token storage. No promise is made for memory-only edits after the browser process is lost.
- Site/Client pages load the published board rather than an editor's unpublished local draft, do not write the editor journal/mirror, and cannot open the editor recovery UI. An editor tab's saved timestamp/dirty marker cannot leave a new audience page empty.

## Data contract and existing functionality

The only published extension is optional `changeEvents[]`, scoped to Work Packages/Workfaces and shared Permits. Each event records `id`, `recordId`, `recordType`, `project`, `action` (created/updated/deleted/restored), `at`, changed-field paths, `revision`, `generation`, and optional self-declared `editorLabel` / operation `reference`. It contains **no full record payloads**. Existing `history` is preserved. Events are combined by unique ID; matching events are not duplicated. Restore appends events instead of erasing later history. A newer board from an older publisher that omits the log cannot silently erase the locally retained log.

Repository/SHA/base/generation/recovery metadata stays browser-local in `oce-ops-integrity-v1`; tokens remain in the existing separate token key. The optional editor label is configured in Settings and is not authenticated. Changing repository destination saves the draft against its existing journal and requires a reload/base review before publication to the new destination.

No Workface, Permit, panel, attachment or spatial record schema was replaced. Original IDs, forms, handlers, completion, retirement and readiness definitions remain authoritative. A local draft may retain a missing approval after deliberate removal and display NO GO; publication/import still rejects invalid or cross-project references. Reconciliation never approves a permit or changes a human verification decision automatically. Readiness derives from the resulting board. The 21 panels, eight workspaces, original-board fallback, project/audience filtering, attachment references and original print sheet remain.

## Limits and remaining acceptance

This is conflict-managed static-file publishing, **not real-time collaboration, secure project access or a certified/tamper-proof audit trail**. Existing Site/Client controls remain display filters; public repository contents must be public-safe. Independent whole-record changes are intentionally not combined at field level. Invalid links need correction before publication. Large JSON boards still depend on browser quota; file/model bytes are not copied into a new storage system. Web Locks/IndexedDB must be available (HTTPS/localhost on supported browsers); failures block safe acknowledgement and direct the editor to export. Grossly damaged journal metadata is retained for export/manual repair rather than guessed or silently overwritten.
