## Explicit Client publication

Scheduled Works' existing planning form has optional `planning.clientLookahead` metadata:
`{ version: 1, enabled: boolean, milestone: boolean, notes: string }`.
Notes are limited to 2,000 characters. Missing metadata means excluded; there is no migration or second register.

Client output also requires the original project/client assignment, panel/item Client flags and active-record display rules. A permitted workface name is shown only when its source Work Package is also permitted. The projection uses the last successfully fetched, validated published board for the current repository identity. An unavailable source never falls back to editor drafts. Local edits require the existing explicit Publish workflow before appearing in Client output.

Allowed fields: recorded activity title, planned dates, permitted workface name, location/chainages, planned quantity/unit, original WFC-003 activity status, explicitly recorded milestone flag and separately entered Client programme notes. Status retains the original rules; “Current planned window” is a date-window label, not measured progress. No new percentage or approval is inferred.

Internal baseline/change records, supervisor/crew/plant, resource references, internal notes, diary information, evidence/attachments, blockers, counts, PPC and production actuals are excluded. Client output provides no editing, commit, publish or administrative controls. Office Client output uses the same published projection, even when the editor has unpublished changes or internal filters.

**Security limitation:** Site/Client display settings are not authentication. GitHub Pages and public `data.json` remain publicly accessible. Do not put confidential information in public board data; this projection does not make underlying public records private.
